# 晾衣架

Tendedero 的本地改版，加了七件事：**复制什么都能挂上绳**、**鼠标悬停放大预览**、**全中文界面**、**超限清理时把最老两张带到你眼前再掉**、**鼠标停着按 Delete 删掉这张**、**一直显示**（绳子常驻，不自动收）、**选择显示在哪块屏**（多显示器下钉住一块）。

原项目：<https://github.com/alejandrobujan/tendedero>（MIT，作者 Alejandro Buján）
本改版按 MIT 要求**自己起了名字、自己画了图标**，不含原作者的名称与图标。

> **2026-11-08 架构变更**：原先「复制什么都能挂」靠外挂程序 `万能挂载` 实现——
> 它监听剪贴板、往截图文件夹写文件，晾衣架再把文件当新截图捡起来。两个进程靠文件夹交接，
> 必须同时开着，少一个就退化。现在这套能力已经**直接长进本工程**（`ClipboardWatcher`），
> 只装一个 App 就够。那个外挂程序不在本仓库内，且已不再需要运行。

## 改了什么

### 1. 悬停放大预览（新增）

鼠标在一张卡片上停 **0.35 秒**，卡片正下方弹出一个大窗：

- **文字卡 / 链接卡** → 直接显示**原文全文**（读卡片自己的扩展属性），不是放大的图片
- **图片卡** → 显示放大后的原图（最多放大 3 倍）

鼠标移开 0.3 秒后收起。这 0.3 秒是故意的：卡片和预览之间有一点缝，不留宽限的话指针还没挪到预览上，预览就先没了。

实现（`Sources/Tendedero/HoverPreview.swift` + `AppDelegate.updateHover`）：
- 复用作者已有的光标轮询 `tick()` 和 `photo(under:)`，不额外起定时器
- 复用 `line.hitRects` 算卡片位置（面板翻转坐标 → 屏幕坐标）
- 预览窗 `ignoresMouseEvents = true`，不抢焦点、不挡下面窗口

### 2. 全中文

- 打包时带入 `zh-Hans.lproj`，共 65 条，**与英文表 100% 对齐，零缺失**
- 译文里的品牌名 `Tendedero` 已替换为「晾衣架」
- 代码里所有界面文字本来就走 `L()` → `NSLocalizedString`，没有硬编码英文

### 3. 超限清理：看得见的那一下（新增）

线挂满以后再复制/截图，原版是**默默**把最老那张清掉——它的位置在屏幕左边看不见的地方，
你只会感觉整排卡片忽然跳了一下。现在改成四步过场（`Line.letGo`）：

1. **滚到最老一头**：线自动滑到最前面，把「要掉的那张」和「它后面那张」两张一起摆到你眼前（0.35 秒）
2. **照原样掉落**：最老那张按原版动画掉下去（下落 520pt、边转边淡出，0.55 秒）——这段动画一行没改
3. **后面那张立刻补到最前面**：不留空位，整排不再等到指针离开绳子才跳一格
4. **滚回最新一头**：掉完之后 0.9 秒滑回最新，接着看刚复制的那张

不滚动的线（「保留在线上」没设，只显示屏宽放得下的张数）最老那张本来就在最前面，
所以跳过第 1、4 步，直接掉落 + 立刻补位。

新卡片正从截图位置飞过来时，第 1 步等它落位（0.7 秒）才开始，否则它飞向的是滚走以后的位置。

如果这台机器开了「辅助功能 → 减弱动态效果」，掉落动画不播（原版行为），只从线上消失。

### 4. 剪贴板：复制什么都能挂（原版能力扩展）

原版只会挂「复制来的图片」，文字和链接复制了没反应。现在三种都挂：

| 复制的东西 | 挂上去的样子 | 点一下卡片 |
|---|---|---|
| 文字 | 文字卡（太长会截断，底部标总字数） | 剪贴板变回**原文全文** |
| 网址 | 链接卡（域名 + 网页标题 + 完整地址） | 剪贴板变回**原网址** |
| 图片 | 原图，不重绘 | 照旧复制图片（原版行为） |

开关在菜单栏里（「挂上复制的内容」），**默认关闭**，第一次要自己打开。

实现要点：

- 文字卡和链接卡是**画成 PNG** 再落盘的（`CardRenderer`）。因为线上的一条就是一个图片文件，
  画成图片才能复用拖拽、复制、QuickLook、Markup 全部能力。220pt 宽是实测「压进 150×104 框里还能读」的上限。
- 原文存在 PNG 自己的**扩展属性**里（`com.local.liangyijia.copiedText`），点卡片时靠它还原。图片卡不存。
  存成扩展属性而不是旁边放一个 `.txt`：删掉图片时原文跟着一起走，不会留下没有主人的孤儿文件。
  单个属性约 128KB 上限，超长的只保留前面一部分并在末尾标注。早期版本用的 `.txt` 旁车仍然能读。
- 判断「用户点了卡片」的依据：`Line.putOnClipboard` 复制卡片时只写 png + 文件路径、**不写纯文本**，
  所以「有 fileURL 又没有 string」这个组合只会在点卡片时出现，不会误伤正常复制。
- 定时器（0.15 秒）**常开**，不受开关控制：关掉只是不再挂新内容，点卡片还原原文还要用它。
- 判断顺序：隐私标记 → 文件 → 文字 → 图片。文字优先于图片，因为 Excel、网页复制富文本时常捎带一张渲染图，
  用户的意图是文字。
- 中文标题乱码的坑：取标题时发 `Range: bytes=0-65535` 会把页面切在多字节字符中间，
  `String(data:encoding:.utf8)` 因为一个坏字节就**整段**判失败，一路退到 Latin-1，
  标题变成 `å‚´å—ç¢—`。改成宽容解码（坏字节占比 < 2% 就认）后正常。

**隐私**：密码管理器、浏览器隐私复制会打 `org.nspasteboard.ConcealedType` 一类标记，命中即丢弃。
但**没有标记的敏感内容照样会挂**——比如从终端复制的 token、密钥。全自动监听本质上就有这个风险，
关掉开关是唯一可靠的办法。

### 5. 鼠标停着按 Delete 删掉这张（新增）

鼠标停在任意一张卡上，按 **Delete**（Mac 键盘上印着 delete 的那个键），这张卡连文件一起进废纸篓，掉落动画照旧。

- 只在**鼠标确实停在卡片上**时生效：鼠标一移开，Delete 立刻恢复成普通的删除键
- 按 Fn+Delete 也行（部分外接键盘）
- 带 ⌘ / ⌥ / ⌃ 的组合不受影响（⌘⌫ 还是删整行）

实现（`AppDelegate.armHoverDelete`）踩过的坑：

| 方案 | 结论 |
|---|---|
| 全局键盘监听 `NSEvent.addGlobalMonitorForEvents` | ❌ 要「输入监控」权限。本项目是 ad-hoc 签名，**每次重新编译签名指纹都变**，系统把它当成另一个 App，授权当场作废——实测重新打包后立刻收不到按键 |
| Carbon 热键 `RegisterEventHotKey` | ✅ 不需要任何权限。悬停时把 Delete 注册成热键，鼠标移开就注销 |

代价是热键会**吃掉**这一次按键，前台 App 收不到。鼠标停在卡片上按 Delete 本来就是要删这张卡，吃掉正好，也顺带避免了「卡片删了、文档里的字也被删了」的双删。

### 6. 一直显示（新增）

菜单栏里多一项 **「一直显示」**，勾上之后绳子常驻屏幕顶上，指针移开也不收回。

| | 关（原版行为） | 开 |
|---|---|---|
| 指针移开 0.5 秒 | 绳子自动收起 | **不收，一直挂着** |
| 新内容挂上 | 闪 2.5 秒再收 | 放下来就不动 |
| 线上空了 | 绳子消失 | **空绳子留在原地**（配一句「看个图，它就会挂在这里」） |
| 全屏 App 挡住 | 收起 | 收起（这是刻意保留的：全屏看片时不该有横条压在上面）；退出全屏后自动回来 |
| 启动 App | 有线才放下来 | 一律放下来 |

想收的时候点菜单「隐藏晾衣绳」照样能收——那是你明确要求的，不会被这个开关拽回来。

**顺带改了一件事**：原版菜单里那个「登录时打开」走的是 `SMAppService`，要求正式签名，本项目是 ad-hoc 签名，点了必然弹错误框。现在它改成**自己读写 `~/Library/LaunchAgents/com.local.liangyijia.plist`**：打勾就写文件、取消就删文件，下次登录自动生效，不需要任何权限。菜单里的勾选状态也改成直接看这个文件在不在。

### 7. 支持 Intel Mac 与 macOS 12（新增）

原来这个包只能装在 Apple Silicon + macOS 14 以上的机器上。现在一个包同时支持两种芯片，最低系统降到 **12（Monterey）**。

| 卡在哪 | 原因 | 改法 |
|---|---|---|
| 最低系统 | `Package.swift` 里声明 `.v14` | 改成 `.v12` |
| `AnyShape` | macOS 13 才引入 | 自己写 `AnyShapeCompat: Shape`，内部统一归一成 `Path` |
| `NSHostingView.sizingOptions` | macOS 13 才引入 | `if #available(macOS 13.0, *)` 才设，12 沿用系统默认 |
| `.onChange(of:) { 旧值, 新值 in }` | 双参数闭包是 macOS 14 才有的 | 新增 `OnChangeCompat`：容器自己记住上一次的值，对外仍给两个参数 |
| 只有一个架构 | 构建脚本只编 arm64 | 两个 `--triple` 各编一次，再用 `lipo -create` 粘成 universal |

实测（本机 Apple Silicon）：`lipo -archs` 输出 `x86_64 arm64`，两个切片的 `minos` 都是 `12.0`，`Info.plist` 的 `LSMinimumSystemVersion` 是 `12.0`，启动正常。

**踩到的坑**：`echo "架构：$ARCHS，..."` 这种「变量紧跟中文全角逗号」的写法，在非 UTF-8 locale 下 bash 3.2 会把汉字的高位字节算进变量名，直接报 `ARCHS<乱码>: unbound variable`。凡是中文标点紧挨变量，一律写 `${ARCHS}`。

**没验证的**：macOS 12 / 13 真机、以及 Intel 机器的实际运行都没测过——手上只有一台 Apple Silicon 新系统。目前只保证「编译通过 + 没有调用 12 不存在的 API」，界面在 12 上会不会有细微错位，需要实测才能确认。

### 8. 选择显示在哪块屏（新增）

接了外接显示器以后，原来的行为是「线跟着你正在用的那块屏走」——在副屏截图，整条线就搬到副屏。
只想让它固定待在一块屏的人（尤其是开了「一直显示」之后），这种跳来跳去很烦。

菜单里多了一项 **显示在 ›**，三种选择：

| 选项 | 行为 |
|---|---|
| 跟随鼠标指针（默认） | 原来那套：截图所在的那块屏、或在菜单栏中部停留的那块屏，线会过去 |
| 主显示器 | 永远钉在带菜单栏、坐标原点的那块屏上 |
| 各块屏的名字（如 `TYPEC`、`显示器 1`） | 钉在某一块具体的屏上 |

钉住之后**新内容不会把线拽走**：在别的屏截图，线还在原处，只闪一下告诉你「有新的了」。
跨屏的「从截图位置飞过来」动画也一并省略——飞不过去，卡片直接落位。

几个实现上的决定：

- **记显示器 UUID，不记 `NSScreen` 对象、也不记 displayID**。`NSScreen` 每次显示器变动都会重建；
  displayID 在拔插、换接口后可能变；UUID 在拔插之间不变，所以外接屏拔掉再插回来能认出是同一块，
  自动把线搬回去。
- **钉住的那块屏被拔掉时，回落到主显示器，但设置原样留着**。插回去就自动回到那块屏，
  用户不会遇到「设置被悄悄改成主屏了」。
- **「主显示器」不能用 `NSScreen.main`**：那是「当前有键盘焦点」的屏，会跟着窗口焦点跑。
  用 `NSScreen.screens.first`（坐标原点那块）。
- **屏幕名字用系统的 `localizedName`**；本机实测主屏返回**空字符串**，
  所以空名按顺序兜底成「显示器 1 / 2」。两块同型号外接屏会重名，这时补上像素分辨率区分。
- **只有一块屏时不显示这一项**——没有可选的东西，多一层子菜单只是噪音。
  但如果之前钉住过（外接屏拔掉了），这一项仍然在，免得用户没法切回「跟随鼠标指针」。
- **换屏后要手动 `objectWillChange.send()`**：`visibleCount`（能挂几张）是普通属性、不发通知，
  不催一次重绘，卡片还按旧屏的张数排在原来的位置。

实测（本机 M1 + 一台 TYPEC 1280×1024 副屏，均为 CGWindow 实测坐标）：

| 场景 | 结果 |
|---|---|
| 跟随鼠标，指针在主屏 | 线在主屏 `x=67 w=1853` |
| 钉住副屏 | 线在副屏 `x=1920 w=1280`，重启后依然 |
| 钉住副屏后在主屏截图 | 线不动，仍在 `x=1920` |
| 钉住一块不存在的屏（模拟拔掉） | 回落到主屏，且 `lineScreen` 设置没被改写 |
| 点「主显示器」 | 立刻搬回主屏，不用重启 |
| 点「跟随鼠标指针」 | 设置键被删掉，线回到指针所在屏 |
| 副屏上的渲染 | 绳子横贯、卡片按 1280 宽重排，无错位 |

## 上限、清理与滚轮（原版自带，这里说清楚怎么用）

这三个能力原版就有，不用改代码，菜单里就能设：

| 能力 | 规则 | 在哪设 |
|---|---|---|
| 同时显示几张 | 按屏幕宽度自动算：`(屏宽 - 200) ÷ 卡距 174`，上限 12、下限 3。1920 宽的屏 = **9 张** | 自动，不用管 |
| 保留上限 | 默认 = 能显示的张数；也可固定 **25 / 50 / 100 张** | 菜单 → `保留在线上` |
| 超出后怎么清理 | 最旧的一张**移入废纸篓**（接管模式下是删文件，不是只从线上移除）；清理过程见上面第 3 节 | 自动 |
| 滚轮回看更早的 | 两指滑动或滚轮；只有当保留数大于能显示的张数时才有「前后」 | 先把保留上限调大 |

实测（1920×1080 屏）：

- 连续复制 14 条 → 文件夹里**精确剩 9 个**（超出即清）
- 保留上限设 25，连续复制 30 条 → **精确剩 25 个**
- 25 张卡片共 **948 KB**，平均 37 KB/张

所以磁盘不用担心：默认 9 张也就百来 KB 级别。想让线上能往回翻历史，就把保留上限调到 25，
这时同时仍然只显示 9 张，多出来的用滚轮滑过去。

## 装

```bash
# 1. 先退出原版 Tendedero 和任何其他剪贴板接管程序，否则会重复监听同一个文件夹，同一张图挂两遍
osascript -e 'tell application "Tendedero" to quit'

# 2. 构建
bash scripts/build-app.sh release

# 3. 装到应用程序文件夹
cp -R "build/晾衣架.app" /Applications/
open "/Applications/晾衣架.app"
```

首次启动会问「让晾衣架接管你的截图？」，点**开启**。

## 开机自启

已经配好，配置文件在 `~/Library/LaunchAgents/com.local.liangyijia.plist`。

**开关在菜单里**：点菜单栏的 T 恤图标 → 「登录时打开」。勾着就是开了；取消勾选会把那个 plist 删掉，下次登录就不再自启。

`~/Library/LaunchAgents/` 这个目录**登录时会被 launchd 自动扫描**，所以写完文件不需要再执行 `launchctl load`。macOS 会弹一条「后台项目已添加」，说明已经登记上。

**怎么确认在生效**：系统设置 → 通用 → **登录项与扩展** → 往下翻「允许在后台」，应该能看到 `Tendedero`（App 的显示名是「晾衣架」，但可执行文件名沿用了 Tendedero，系统按可执行文件名显示）。开关保持打开。

**如果没有生效**，在「终端」里手动加载一次（终端有完整权限，这里的自动化环境没有）：

```bash
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.local.liangyijia.plist
```

想临时关掉自启又不想删文件：

```bash
launchctl bootout gui/$(id -u)/com.local.liangyijia
```

彻底不要了就直接删那个 plist。

**为什么不用 App 内的「开机启动」开关**：那套要走 `SMAppService`，要求正式签名；本项目是 ad-hoc 签名，注册必然失败。LaunchAgent 不挑签名。

**为什么 KeepAlive 故意不写**：写 `true` 的话，你从菜单里退出，launchd 会立刻把它拉回来，像甩不掉。现在的行为是「登录时起来一次，你退出就退出」。

## 注意

| 项 | 说明 |
|---|---|
| bundle id | `com.local.liangyijia`，与原版 `app.tendedero.Tendedero` 独立 |
| 偏好设置 | 因为 id 变了，原版的设置不会带过来，需要重新开一次「接管截图」 |
| 双开 | **绝对不要**原版和改版同时运行，会重复挂载 |
| 重新编译 | ad-hoc 签名，每次重编 macOS 会重新问一次文件夹访问权限 |
| 自动更新 | 没有。上游更新要自己合并 |

## 调试开关

```bash
HOVER_DEMO=1 ./build/晾衣架.app/Contents/MacOS/Tendedero
```

设了这个环境变量，预览会无视鼠标、直接对第一张卡显示，用来在没有辅助功能权限时验收渲染。

## 配套（已合并，不必再装）

早期这套能力是**外挂形态**：一个独立的菜单栏程序，监听剪贴板，把卡片写进截图文件夹，
晾衣架再当新截图捡起来。它的逻辑现在已经在 `ClipboardWatcher` 里，
**不需要再运行，也不建议运行**——两个进程同时写同一个文件夹，同一条内容会挂两遍
（合并当天就踩到了：一次复制挂出两张，相隔 4 毫秒）。那个程序不在本仓库内。
